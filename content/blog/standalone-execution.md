# OntoBDC: Standalone Offline Dataset Execution

A paradigm-shifting architecture for processing semantic data and ontologies locally, directly in the browser, without requiring any backend infrastructure or software installation.

---

## 🎯 The Objective

The primary goal of this architecture is to achieve true **Software-Independent Data**. 

In modern semantic web and linked data applications—such as the **Digital Product Passport (DPP)**—the reliance on complex cloud infrastructure, graph databases, and heavy APIs creates a massive barrier to entry and compromises data sovereignty.

This solution ensures that raw files (CSVs, JSONs) and their semantic rules (Ontologies in RDF/TTL) can work side-by-side, autonomously. The user receives a data package and can validate, query, and process it using nothing but a standard web browser. If the internet goes down or the original server disappears, the data remains fully functional, auditable, and readable.

## ⚙️ How It Works

We transformed a standard static `index.html` into a fully-fledged local semantic execution engine. Here is the step-by-step breakdown of the underlying magic:

### 1. Bypassing Browser Security (CORS) via Directory Upload
Browsers strictly prohibit local HTML files (`file:///`) from reading other local files due to CORS and Same-Origin security policies. 
To bypass this without forcing the user to run a local HTTP server, we implemented an HTML5 Directory Picker (`<input type="file" webkitdirectory />`). 
The user simply selects the dataset folder, granting the browser explicit permission to read the raw files in memory.

### 2. The Pyodide Virtual Machine
Since the core processing engine of OntoBDC is written in Python, we embedded **Pyodide** (a Python distribution compiled to WebAssembly) inside the HTML.
When the user uploads the dataset folder, JavaScript intercepts the files and dynamically reconstructs the folder hierarchy inside Pyodide's virtual, in-memory filesystem (`/tmp/dataset`).

### 3. Native Package Installation on the Fly
Once the virtual filesystem is ready, the script uses `micropip` (Pyodide's package manager) to dynamically download the official `ontobdc` engine directly from PyPI. This guarantees that the execution is running the actual, official semantic processor.

### 4. Memory Mocking for Heavy Dependencies
To ensure the application loads in seconds rather than minutes, we intercepted Python's `sys.modules`. 
Heavy, native-compiled dependencies like *Frictionless*, *RO-Crate*, *Spacy*, and *Numpy* were completely "mocked" (replaced by lightweight dummy objects in memory). The Python core believes it is using the full libraries, but under the hood, we provided custom lightweight implementations specifically tailored to read the CSVs and RDFs needed for the dataset.

### 5. Seamless Execution & Output Injection
Finally, the local Python script (`dataset.py`) is executed. We patched Python's `sys.stdout` so that any `print()` or output generated by the OntoBDC capability bypasses the hidden terminal and is injected directly into the HTML DOM. 
The result is a beautifully formatted, semantic JSON output rendered right in the user's view.

## 🚀 Use Cases & Applications

- **Digital Product Passports (DPP):** Companies can distribute product data packages that auditors or clients can verify locally, ensuring full transparency without vendor lock-in.
- **Decentralized Auditing:** Anyone can validate if a dataset complies with its ontology rules locally.
- **Archival & Compliance:** Data packages remain eternally readable. As long as web browsers exist, the data can be parsed and understood.
- **Frictionless Distribution:** Datasets can be shared via email, USB drives, or IPFS as a simple `.zip` file containing the raw data and the `index.html` player.

## 💡 Conclusion

By leveraging WebAssembly and clever filesystem mounting, we have effectively decoupled the data from the software. The HTML file acts merely as a universal "player" for the data, proving that true semantic decentralization is not only possible but can be highly accessible to non-technical users.
